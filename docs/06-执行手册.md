# 执行手册

本文档是实现阶段的唯一指令来源。执行者按 T01 → T24 顺序推进，每个任务跑完验收再进下一个。

01–05 号文档是设计依据；本文档与它们冲突时，**以本文档为准**（已消解的歧义见第 5 节末）。

---

## 0. 执行者规则

1. **顺序执行**，不得重排任务。每个任务完成后必须跑该任务的「验收」，失败则修到通过，不进入下一任务。
2. **不得引入新依赖**。允许的第三方代码只有 `vendor/gsap.min.js`（从 `../pets/vendor/gsap.min.js` 复制）。不使用 React / Vue / TypeScript / Phaser / 任何构建框架。
3. **所有可调数值只写在 `src/data.js`**。其他文件出现魔法数字视为不合格。平衡调参只改 `data.js`。
4. **素材缺失不得阻塞**。`core/assets.js` 必须在文件不存在时自动生成带文字标签的占位色块，T01–T23 全程可用占位图工作，正式素材统一在 T24 替换。
5. **注释规则**：中文；只描述紧邻代码做了什么；不写文件产出方式、不写变更记录、不写"暂时/待办/参见某文档"、不写设计理由长文；不出现任何 AI 或工具署名。标识符与提交信息用英文。
6. **不得静默缩小范围**。若某任务确实做不动，先把该任务其余部分做完，然后明确写出没做的部分和原因。
7. 报告完成前必须真的跑过验收命令，并贴出输出。

## 2. 技术基线

- 渲染：单 `<canvas>` + Canvas 2D。
- 语言：原生 ES Modules，esbuild 打包成 `game.bundle.js`。
- UI 分工：**顶栏、升级商店、日结算、报纸结算、横屏提示用 DOM + CSS**；顾客、柜台、工位、物品、粒子用 Canvas。
- 补间：`vendor/gsap.min.js`。
- 音频：手写 Web Audio（需要 `playbackRate` 变调做外星语音，不引入音频库）。
- 存档：localStorage 单槽。

若后续改用 Phaser 或 Cocos，只有 T01–T05、T22、T23 需要重写，T06–T21 的数据与逻辑层原样可用。

## 4. 全局约定

**坐标系**：全部使用 1280×720 逻辑坐标。`main.js` 负责把 canvas 的 CSS 尺寸按 `min(vw/1280, vh/720)` 缩放并居中，`ctx.setTransform(scale*dpr, 0, 0, scale*dpr, offsetX*dpr, offsetY*dpr)`，业务代码不感知 dpr。

**分区**（y 轴）：顶栏 0–64（DOM）｜顾客队列 64–300｜柜台操作 300–600｜底栏 600–720。

**渲染层序**（从后到前）：背景 → 店面 → 顾客 → 柜台前景板 → 备料格与机器 → 台面物品 → 星币 → 粒子 → Canvas 浮层（气泡、耐心条）→ DOM 面板。

**命名**：文件与素材全小写下划线；素材 `类别_名称_状态.png`；状态机状态用大写常量。

**点击区**：最小 88×88 逻辑像素。每帧由绘制模块注册，指针事件从最高 z 往下命中，命中即停。

**性能红线**：同屏精灵 ≤80，粒子 ≤200；粒子与台面物品走对象池；每帧不得创建对象；发光图与染色图按 (贴图,颜色) 缓存到离屏 canvas，只算一次。

### 已消解的歧义（覆盖 03 号文档）

1. **备料区四格的开放节奏**：格 1 肉柱、格 2 触须自第 1 天开放；格 3 星云酱由一星解锁；格 4 反物质辣椒由 C5 解锁。薯条走炸锅暂存盘，糖浆走卷制台旁按钮，二者**不占备料槽**。
2. **烤肉库存与质量**：不再存或判定肉柱火候相位；点击切片只消耗库存并生成固定满质量 `q = 1` 的肉片。库存耗尽后由 ARM-7 补货。
3. **谜语暗访**：共 6 组（上表），三次暗访各随机抽 1 组且不重复。
4. **三星终审的"连续 3 单"**：指第 30 天内连续 3 笔非事件顾客订单，中间出现超时或事件顾客不打断计数，出现 `S < 0.90` 则重新计数。
5. **焚化炉与扫地机器人已替换为外星生物**，机制不变、id 不变，只换表现与素材：
   - 「丢给 ARM-7 焚化」→ **丢给口器花吞掉**。`stations.js` 的动作名仍是 `discard()`，`TIMING.incinerate` 仍是耗时字段。ARM-7 只负责补货，不再负责销毁。
   - 「扫地机器人吸走星币」→ **拾荒蛞蝓爬来吞掉**。`TIMING.coinLife` 仍是判定字段；升级 `A10` 的 `effect` 仍是 `autoCoin`（表现为蛞蝓被驯化，改为替玩家收币），显示名可写「驯化拾荒蛞蝓」。
6. **外星生物不参与任何判定**。`entities/bio.js` 只做表现与素材切换，判定留在 `stations.js` / `day.js`。唯一例外是星门蟑螂给的 `+1` 星币，走 `day.js` 的正常收入路径并受 `BIO.roach.dailyCap` 限制。

## 6. 模块契约

只列跨模块的公开接口。未列出的一切都是模块私有。

### `core/engine.js`
```js
createEngine({ canvas, update, render }) -> { start(), stop(), now }
```
固定步长 `dt = 1/60`，累加器补帧，单帧最多补 3 次。`update(dt)` 只改状态，`render(ctx)` 只读状态。

### `core/assets.js`
```js
await load(manifest, onProgress) // manifest: { images: {name: path}, audio: {name: path} }
img(name)   -> HTMLImageElement | HTMLCanvasElement   // 缺失时返回占位图
buf(name)   -> AudioBuffer | null
anchor(name)-> { x, y }                                // 默认 {x:0.5, y:1.0}
```
**占位图规则**：加载失败时生成一张对应尺寸的画布，填 `PALETTE.panelLit`，描 2px `PALETTE.neonPink` 边，居中画出素材名。整局游戏可在零素材下运行。

### `core/input.js`
```js
beginFrame()                                  // 清空本帧点击区
zone(id, { x, y, w, h }, z, onTap)            // 矩形点击区，z 越大越上层
circleZone(id, { x, y, r }, z, onTap)
bindPointer(canvas, toLogical)                // 注册一次
```
指针按下时从最高 z 往下命中，命中即调 `onTap` 并停止。

### `core/render.js`
```js
sprite(ctx, name, x, y, opt)   // opt: { anchor, scale, rot, alpha, tint, glow, flipX }
nineSlice(ctx, name, x, y, w, h, inset)
text(ctx, str, x, y, opt)      // opt: { font, size, color, align, baseline, tabular }
bar(ctx, x, y, w, h, ratio, colorFill, colorBg)
glowCache / tintCache          // 内部按 (name,color) 缓存离屏画布
```

### `core/state.js`
```js
state    // 单一可变对象
save() / load() / reset()
```
存档键 `cosmic_shawarma_save_v1`。字段：
```js
{
  version: 1, day: 1, coins: 0, rep: 0, stars: 0,
  shopLevel: 1, upgradesA: [], menuC: [],
  inspector: { pending: 1, retries: 0, nextDay: 5, usedRiddles: [] },
  stats: { revenue: 0, orders: 0, perfect: 0, maxTicket: 0 },
}
```
每日结算时写入。

### `core/audio.js`
```js
unlock()                       // 首次指针事件调用
sfx(name, { pitch = 1, gain = 1 })
voice(name, pitchRange)        // 在 ±4 半音内随机变调
bgm(name, { loop = true })
setMuted(bool)
```


```js
{
  id, wrap: { meat:0, tentacle:0, sauce:0, pepper:0, fries:0, syrup:0 },
  snack: 'fries' | null, drink: 'soda'|'nova'|'plasma'|null,
  riddle: string | null, basePrice: number,
}
```

### `systems/scoring.js`（**纯逻辑，不得引用 canvas / DOM**）
```js
scoreOrder(order, product, patienceLeftRatio, opt) -> {
  S, A, W, H, tip, repDelta, perfect, income
}
```
Product 形状：
```js
{ wrap: {...同上}, snack, drink, heats: number[], friesBest: boolean }
```
计算：
```
missing = Σ max(0, order[k] - product[k])  + (snack/drink 缺失各计 1)
extra   = Σ max(0, product[k] - order[k])  + (snack/drink 多余各计 1)
A = max(0, 1 - missing*0.34 - extra*0.25)
W = patienceLeftRatio                       // 0..1
H = heats 与薯条质量的均值；无火候部件时 = 1.0
    薯条：熟 1.0，最佳窗口内 1.15（上限裁到 1.0 之后再算均值前不裁）
S = clamp(0, 1, 0.40*A + 0.40*W + 0.20*H)
tip = 0.5 + 1.5*S
repDelta = round(-6 + 16*S)
perfect = S >= 0.97
income = order.basePrice * shopPriceMul * starMul * customerPriceMul * tip
         * (perfect ? 1.5 : 1)
```
谜语单额外判定 `need` / `forbid` / `maxKinds` / `needDrink`，不满足则该单 `riddleOk = false`（不影响 S）。

### `systems/stations.js`
每个工位一个状态机，导出 `update(dt)` 与供 UI 调用的动作函数：
`sliceMeat() addFromTray(slot) addExtra(id) roll() pack() dropFries() takeFries() addFries() takeCup() pour(drinkId) discard() restock() serveTo(customerId)`
自动化由 `systems/automation.js` 读 `state.upgradesA` 后在每帧代为调用这些动作，**工位本身不感知升级**。

### `systems/day.js`
```js
startDay() / update(dt) / endDay() -> DaySummary
```
`DaySummary`: `{ revenue, orders, perfect, repDelta, star }`。

### `entities/customer.js`
```js
spawn(def, slotIndex) / update(dt) / patienceRatio / setMood(m) / leave(reason)
```
换头组合：身体取 `body_{def.body}.png`，头取 `head_{def.id}_{mood}.png`（`moods === 1` 时固定取 `head_{def.id}.png`）。

若 `def.variants` 存在，spawn 时在 `[def.id, ...def.variants]` 中随机取一个作为**头部素材的 id**，其余一切行为数据仍用 `def`。变体只有单表情。

### `entities/bio.js`
```js
maw.feed(item)            // 口器花吞掉废品，返回吞食耗时
slug.chase(coin)          // 蛞蝓爬向指定星币；A10 后改为替玩家收取
jelly.update(dt)          // 氛围照明，只有渲染
roach.update(dt)          // 按 BIO.roach 的间隔与每日上限生成，被点则给 reward
```
四种生物共用 `IDLE` 表驱动的活性动画，不含任何玩法判定——判定仍在 `stations.js` 与 `day.js` 里。

### UI 模块
`ui/hud.js` `ui/counter.js` 画 Canvas；`ui/menu.js` `ui/shop.js` `ui/settle.js` `ui/headline.js` 操作 DOM，各导出 `show(data)` / `hide()`，显示期间暂停 `day.update`。`systems/achievements.js` 负责成就解锁与存档。
