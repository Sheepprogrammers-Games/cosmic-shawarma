# 技术方案与排期

## 1. 技术选型

| 项 | 选择 | 理由 |
| :--- | :--- | :--- |
| 渲染 | Canvas 2D，单画布 | 单屏、无物理、素材少，2D 上下文足够；比引擎少几百 KB |
| 语言 | 原生 ES Modules，无框架 | 与同目录已有项目一致，无依赖，构建最快 |
| 构建 | esbuild 打包为 `game.bundle.js` | 单文件产出，首屏一次请求 |
| UI | 顶栏、商店、结算面板用 DOM + CSS；游戏区用 Canvas | 面板类 UI 用 DOM 写得快、文字排版可靠；Canvas 只画游戏世界 |
| 存档 | localStorage 单槽 | 无账号需求 |
| 音频 | Web Audio API，单 AudioContext，首次交互后解锁 | 移动端自动播放限制的标准解法 |
| 适配 | 逻辑 1280×720，等比缩放 letterbox；竖屏显示横屏提示 | 一套坐标系，不做响应式布局 |

不使用 Phaser / PixiJS：本作没有需要引擎的部分（无 tilemap、无物理、无骨骼动画），引入只会增加包体与调试面。

## 3. 关键实现要点

**主循环**：固定时间步 `dt = 1/60`，累加器补帧，最多补 3 帧。所有工位状态机在 `update(dt)` 里推进，渲染只读状态。

**命中测试**：每帧由各绘制模块把矩形/圆形点击区注册进 `input.js` 的 z 序列表，指针事件从最上层往下命中，命中即停。这样点击区永远与画面一致，不会错位。

**渲染顺序**：背景 → 店面 → 顾客队列 → 柜台前景板 → 备料格与机器 → 台面物品 → 星币 → 粒子 → Canvas 内浮层（气泡、耐心条）→ DOM 面板。

**发光实现**：不用 CSS filter（Canvas 内无效）。用 `shadowColor` + `shadowBlur` 画两遍，或预先在离屏 canvas 生成发光图缓存，按物件类型缓存一次即可，避免每帧重算。

**染色特效**：白色特效贴图用 `globalCompositeOperation = 'multiply'` 在离屏 canvas 上染色后缓存，按 (贴图, 颜色) 做 Map 缓存。

**性能预算**：目标 60fps（中端手机 ≥45fps）。同屏精灵上限 80，粒子上限 200，超出时按存活时间淘汰。禁止每帧创建对象，粒子与物品走对象池。

**包体预算**：`game.bundle.js` ≤ 300KB（未压缩）、图片 ≤ 5MB、音频 ≤ 3MB，首屏只加载背景 + UI + 前 2 种食材，其余在首日营业中懒加载。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
| :--- | :--- | :--- |
| 素材量最大，最容易拖垮进度 | 高 | 换头共用身体、分层叠加渲染饼上料、粒子替序列帧、店面四级同底稿迭代；实际绘制量压到约 45 张 |
| AI 生成风格不统一 | 高 | 先定 3 张锚定图；每张出图强制走抠图/色板映射/重描边三步后处理 |
| 数值失衡导致 30 天太长或太短 | 中 | D4 留出专门的平衡时段；价格表按"第 N 天负担得起"倒推，调参只动一张表 |
| 移动端音频不响 | 中 | 首次触摸解锁 AudioContext，并做静音降级不影响玩法 |
| 谜语暗访玩家看不懂 | 中 | 谜语失败不硬性失败，按普通单评分，仅拿不到星；连续两次失败后气泡追加配料提示 |
| 4 天工期不足 | 中 | 严格按 P0/P1/P2 砍；P2 全砍仍是完整可通关作品 |
| 焦糊/溢出机制过于劝退 | 低 | 焦糊只损失一篮不损失订单；自动炸锅与快速补给提供明确解法 |
